## Legend

- **Breaks** — expected blast radius of the proposed split, not yet verified by build/test.
  - `rename only` — file renamed to match its sole/primary type; no type or namespace change; zero API impact.
  - `split only` — extra types extracted to sibling files in the same namespace; no rename, no API impact.
  - `rename + split` — both of the above.
  - `high churn` — module used widely across `ChallengePass`; coordinate before executing.
- **Annotation needed** — `Yes`: every new/renamed file must get the AGENTS.md copyright header (updated `file="..."` to match new name) and, for any touched function, the mandatory purpose/call-frequency/scope doc comment. This column is about the **cross-PR duplication comments** reviewers will see: it flags that reviewing the header/doc-comment diff once, on the owning layer where the split first lands, is sufficient — the identical diff reappearing on each downstream PR (`m1` → `m2` → `m3` → `m4`) as the split merges up is expected merge noise, not a fresh review item, and should not be re-litigated on every branch.

## Open before Stage 2 approval

- **Callers filled (2026-07-26)** via `\\bTypeName\\b` grep across Core, ChallengePass, Shell, Tests, and E2E on `prototype/maui-m4`. `Breaks` remains an estimate until each split is build-verified. Re-check Shell compile gate after every batch.
- **Shell compile gate.** The caller search above must include the MAUI Shell (`CipherBank-app/` — view models, platform services, and DI registration), not just `Core` and `ChallengePass`. Stage 1 already produced one Critical finding of exactly this shape: Core API signatures changed without mapping Shell call sites, and the Shell stopped compiling even though `Core` and the 267-test suite were green. The fix landed as **zero-token default interface methods (DIMs)** on the affected `Core` interfaces (`IProductApi`, `IStepUpAuth`, `IMnemonicBackupService`, `IWalletService`, etc.), forwarding to the `CancellationToken`-required member — that is the **Stage 1 compatibility strategy** for keeping interface-typed call sites source-compatible without reintroducing optional parameters on abstract interface slots. Renames and type moves in Stage 2 have the same blast radius, so **every Stage 2 PR must build `CipherBank-app/CipherBank-app.csproj`, not only run `dotnet test`**, and the caller mapping in step 2 must explicitly cover Shell ViewModels (the layer where the Stage 1 break actually surfaced). Note the Shell only exists in full from `prototype/maui-m3` upward, so the compile gate runs there even when the split itself lands on `m1`.
